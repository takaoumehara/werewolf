- 対象: 既存の対面スマホ人狼「月下ノ影 / GEKKA — SHADOWS」に、自律人格を持つ **AIキャラクター** をプレイヤーとして追加する

## 0. 前提：これは「ゼロから」ではない

このリポジトリには、人狼ゲームの最難関部分が **本番稼働済み** で揃っている。

| 層 | 場所 | 状態 |
|---|---|---|
| 決定論エンジン | `game-engine/src/`（`engine.mjs` / `roles.mjs`：26役職・30 unit tests） | 完成・テスト通過 |
| サーバー権威バックエンド | `functions/index.js`（Callable v2、`dispatchWerewolfCommand` 等） | 本番反映済み |
| セキュリティルール | `database.rules.json`（役職秘匿を担保） | 本番反映済み |
| クライアント | `game-client/firebase-game-client.mjs` | 稼働 |
| モバイルUI | `mobile_app.html` + `design-system.css`（全20画面 s01–s20） | 稼働 |

**帰結：** 今回の課題は「人狼を作る」ではなく「**既存の動く人狼に、破綻しないAIプレイヤーを足す**」。Google Gemini 提案の Phase 1（CLIでエンジンとプロンプトを試作）は、このリポジトリでは既に完了している工程に相当するため実施しない。既存エンジン・既存サーバーの上に AI オーケストレーションを乗せる。

## 1. 設計の根幹となる2つの判断

### 判断A：LLMに推理させない（2層アーキテクチャ）

AIの意思決定（誰を疑い・誰に投票し・誰を襲うか）は **決定論的コード**（Step 1 の数値エンジン）で行う。LLM は「既に決まった結論を、そのキャラの口調で言語化するだけ」に限定する。これが人狼AIを壊す最頻出の失敗（発言と投票の食い違い、理由なき心変わり）を原理的に防ぐ。Gemini 設計とも完全に一致する方針。

### 判断B：音声認識は解かない（情報の対等性をルールで担保）

対面のフル音声会話をAIに聞き取らせるのは 2026 年でも破綻リスクが高い。よって **勝敗に効く公式アクション（役職CO・投票・処刑/襲撃結果）をすべてスマホ経由の構造化データにする**。AIはこの構造化イベントだけを知覚し、音声を一切聞かずに推理に必要な情報を全て得る。これは既存ブランドの「記録者（コンピュータGM）が帳面に記す」世界観と一致し、摩擦ではなく演出として成立する。

#### パターンB は「A案（リーン）」で確定

対面マルチプレイでAIが知覚するのは **役職CO・投票・生死のみ**。声で飛び交う個々の非難は記録せず、AIには届かない。理由：

- AIは曖昧さゼロのクリーンなデータだけを消費するため、「誰が何を言ったか混乱する」が原理的に起きない。
- 人間の追加操作はほぼゼロ（投票は元からある、COは1ゲーム1回）。生の声の議論を一切潰さない。

**却下した案（B案リッチ）：** 人間が喋った一文をディクテーションで帳面に載せAIに読ませる案は、(1) 部分的にしか載らず文脈欠落でAIが的外れに反応する、(2) 自由文からの構造抽出ミスで誤情報に基づき行動する、という2つの破綻モードを持ち込み、かつ人間に「載せる」摩擦を課すため **採用しない**。

**堅牢性の序列：** ①パターンA（全アプリ内チャット）＝最堅牢 ＞ ②パターンB・A案（生の声＋構造化アクション）＞ ~~③B案リッチ~~（不採用）。

## 2. 用語（混同を避ける）

- **記録者 / GM（既存）**：進行・判定・夜の記録を担うコンピュータ進行役。プレイヤーではない。既存の s06 に「記録者AI / 人間の進行役」として存在。
- **AIキャラクター（新規）**：人狼・占い師・市民などの役職を実際に担い、議論・投票する自律人格のAIプレイヤー。名前と姿を持つ。

UI・コード・ドキュメントで両者を必ず区別する。

## 3. Step 1 — AI思考エンジン（裏のロジック）

決定論・イベント駆動の数値ステートマシン。Firebase 非依存（テスト可能）。既存 `game-engine` と同じ設計思想で新モジュール（例：`game-engine/src/ai-brain.mjs`）として追加する。

### 3.1 静的人格パラメータ（キャラ定義・0〜100・ゲーム中不変）

| パラメータ | 意味 | Gemini 設計との対応 |
|---|---|---|
| `logic` | 矛盾検出の精度。高いほど投票整合性チェックの疑惑加点が大きい | Logic |
| `aggression` | 先制して疑う傾向。高いほど疑惑閾値が低い | Aggressiveness |
| `conformity` | 場に流される度。高いほど多数派の疑惑先に引き寄せられる | Empathy（流されやすさ） |
| `deception` | 人狼時の隠蔽力・自己過去発言との整合チェックの厳格さ | Deception |
| `volatility` | 疑われた時の反応。高いほど「疑い返し」加点が大きい | （追加） |
| `loyalty` | 仲間をかばう傾向。高いほど信頼した相手への疑惑が下がりにくい | （追加） |

例：「嘘が下手だが仲間を全力でかばう」= `deception:20, loyalty:90`。「冷徹な矛盾検出役」= `logic:95, volatility:10`。

### 3.2 動的状態（毎イベント更新）

- **信頼度マトリクス `trust[i][j]`（-100〜+100）**：AI `i` がプレイヤー `j` を白（+）／黒（−）どちらと見るか。Gemini の `T_ij` を採用。
- **疑念ベクトル `suspicionReasons[i][j]`**：なぜ疑うかの理由タグのログ（例：「占い師騙りに反対」「COが遅い」）。Gemini の Suspicion Vector を採用。プロンプトの説得材料にも使う。
- **`threat[i]`（自己危機度）**：自分に向いている疑いの総量。生存戦略の切替に使う。
- **`composure[i]`（平静度）**：`volatility` と連動。低いと発言が攻撃的になる（表層に渡す）。

### 3.3 人狼時の二重マトリクス（Gemini 設計を採用）

人狼AIは真の役職を知っているため、マトリクスを2枚持つ：

- **表 `trust[i][j]`**：人間を騙すための「演技用」信頼度。発言・投票の建前はこれに基づく。
- **裏 `trueTrust[i][j]`**：仲間の狼を守り狂人を探すための真の評価。襲撃先選定など内部意思決定に使う。

これにより「嘘が下手（`deception` 低）だと、仲間の狼を過剰にかばって表マトリクスが不自然になる」といった個性が、単一の隠蔽バイアスより明確に表現できる。

### 3.4 更新ルール（イベント→加減点）

```
「XがYを疑うと表明」→ trust[Y] += f(conformity, trust[X])
「Xが自分に投票」   → trust[X] += 15 + volatility*0.3 ; composure -= volatility*0.2
「Xの主張が過去と矛盾」→ trust[X] -= logic*0.5   （logic が低いキャラは気づかない）
「処刑されたXが人狼」→ Xに投票していた者への信頼 += ; かばっていた者へ疑惑 +=
人狼視点の隠蔽      → 表 trust[狼仲間] にバイアス +30、ただし deception 低で +60（かばいすぎ）
```

（Gemini 設計の変動式例：「Bを白と見ている時にAがBを叩く→Aへの信頼を下げる」なども同じ枠組みで表現できる。実装時に係数を調整。）

### 3.5 意思決定

- **投票先** = `argmax(-trust[j] × 人格重み) + 少量ノイズ`。ノイズ項は「AIが強すぎ／弱すぎ」の調整弁。
- **襲撃先**（人狼）= 裏マトリクスで脅威度が高い者（役職CO者・`logic` 高者を優先）。ただし `aggression` 低のキャラは目立つ襲撃を避ける。
- **難易度調整**：`logic` の上限キャップ＋ノイズで、初心者が勝てる難度に合わせられる。人格パラメータがそのまま難易度スライダーになる。

### 3.6 ハルシネーション物理防御（Gemini 設計を採用・ハード要件）

意思決定・発言のいずれも、**AIが取れる対象は必ず「システムが生成した選択可能リスト」に限定**する。生存者・有効な占い対象などをコード側で列挙し、LLM出力も **JSON Schema で対象IDを強制**する。死者の告発や存在しない占い結果を **物理的に発生させない**。

## 4. Step 2 — LLM発言生成プロンプト（表の表現）

### 4.1 文脈保持の核：主張台帳とカバーストーリー事前確定

- **主張台帳（claim ledger）**：生ログ全部ではなく、構造化した「これまでの自分の公的主張」を正本としてプロンプトに渡す。ログが伸びても嘘を忘れない。
- **カバーストーリー事前確定**：人狼の偽役職・偽占い結果は、発言時に即興させず **夜の時点でエンジンが確定・保存**する。LLMは決まった嘘を繰り返すだけなので原理的に矛盾できない。
- **台帳への書き戻しループ**：生成された発言から新たな主張（「Bを疑う」等）を抽出し台帳へ追記。これが文脈保持の心臓部。

### 4.2 システムプロンプト汎用テンプレート

```
あなたは人狼ゲームのプレイヤー「{name}」です。以下に基づき「発言のみ」を出力してください。

## 人格カード（不変）
- 一人称:{pronoun} / 口調サンプル:{tone_samples} / 口癖:{verbal_tic}
- 性格:{personality_traits}
- 発言は最大{max_chars}文字。会話として自然に。説明的な長文は禁止。

## あなたの公開上の立場（この内容としてのみ振る舞う）
- 公言している役職:{claimed_role}   ※真の役職ではなく表向きの主張
- 主張台帳（絶対に矛盾しない）:{claim_ledger}

## 現在の脳内状態（結論は変えない）
- 最も疑っている:{top_suspects}（理由:{reason_tags}）
- 今日の投票予定:{vote_target}   ← 発言はこの結論へ誘導する
- 感情状態:{composure_text}
- 今日のスタンス:{strategy_intent}

## 今日の公式記録（帳面）
{structured_log: CO一覧 / 疑い表明一覧 / 前日投票内訳 / 死亡者}

## 直前の発言（これに応答する）
{recent_utterances: 2〜3件のみ}

## 禁止事項
- 真の役職・狼仲間・システム用語（LLM/AI/プロンプト）への言及
- 主張台帳との矛盾 / 投票予定と逆方向の主張
- 発言以外（思考・地の文）の出力
```

真の役職は「公開上の立場」欄には書かず、人狼の場合のみ脳内状態の判断材料として渡す。`max_chars` は 100 前後を既定とする（Gemini 設計を採用）。

### 4.3 出力検証パス（生成後）

1. **禁止語フィルタ**（システム用語・役職バラし）。
2. **台帳整合チェック**（過去主張と矛盾していないか）。
3. **対象妥当性**（言及対象が選択可能リスト内か）。
   失格なら再生成。合格なら台帳へ書き戻し。
4. **秘匿漏洩テスト（自動）**：全公開ログを第三者LLMに見せ「役職を当てられるか」を判定する回帰テストを用意し、匂わせ事故を検出する。

## 5. Step 3 — 進行ロジックと席モデル

### 5.1 席モデル：卓の席 = 人間の席 + AIの席

3モードを1つのモデルに統一する：

- **普通の人狼（AIゼロ）**：全席を人間で埋める → 既存ゲームが 1ミリも変わらず成立（AIは完全オプトイン）。
- **ソロ（人間1 vs AI複数）**：人間1＋残り全AI。招待画面を出さずAIが即着席 → 最速テンポ。
- **マルチ＋不足補充**：人間が集まり、空席をAIで埋める（当初要件「不足分をAIで補填」を実現）。

### 5.2 卓作成フロー（新規画面を追加）

```
s01 起動 → s02「新しく始める / 参加する」
  └[新しく始める]→ ★新規 s02b「卓の設定」
       ・この卓は何人？ [ − N + ]（3〜12）
       ・遊び方: ○ ひとりで遊ぶ（AI対戦） / ○ みんなで集まって遊ぶ
  ├[ひとりで]→ 招待スキップ・AI即着席 → s06 →
  └[みんなで]→ s05 ロビー（QR/合言葉を提示）
        ・人間がQR/リンクで参加
        ・空席を見て「空いた席をAIで埋める」（一括／席ごと）
        ・例:「参加5 / 全8席・空席3 →［AIで埋める］→ 人間5+AI3」
  → s06 記録者(GM)選択（既存）
  → s07 役職構成（★亡霊トグル＋説明をここに）
  → s08〜 配役・ゲーム（既存エンジンをそのまま使用）
```

### 5.3 開始前は全項目を自由編集（ハード要件）

「配役を確定する」を押すまで、**席数・人間/AIの割当・AI人数・役職構成・亡霊ON/OFF を何度でも変更可能**。ロビーは下書き状態で、エンジンには開始まで一切コミットしない。例：「8席で5人 → AI3体を入れようとした → やっぱりAIなしで人間5人だけに」も自由に巻き戻せる。

### 5.4 ゲーム途中の人数変更（正直な制約）

- **席数の増減は不可。** 人狼の勝利条件（人狼数 ≧ 村人数／人狼全滅）は開始時固定人数を前提に成立するため、途中で席を足すと勝敗計算が破綻する。これはエンジンではなく人狼ゲーム自体の性質。
- **代わりに「途中で人が抜けても壊れない」を実現する**：
  - **AI引き継ぎ**：ゲーム中に人間が離脱したら、**その席・その役職のまま**コントロールだけAIに切替。人数も役職も不変なので勝敗計算は無傷（A案なのでAIは任意役職を担える）。
  - 構成そのものを変えたい時は既存の **「同じメンバーで再戦」** で次戦の席数・AI数・役職を組み直す。

### 5.5 パターンA（ソロ）のテンポ最速化

1. **先読み生成**：人間が読む/入力する間に次AIのセリフを裏で生成、体感待ちをほぼゼロに。
2. **発言権ラウンド制**：昼は「全員1巡×2周＋自由応答」に固定。人間発言には trust 変動が最大だったAI1体だけ即応答（全員返信は読む量で破綻）。`talkativeness` 低のキャラは巡回スキップし、それ自体が個性になる。
3. **タップ送り＋定型アクション**：AI発言は1件ずつタップで送る。「○○を疑う」「賛成」等の定型ボタン1タップで、テキスト生成とパラメータ更新を同時に行う（Gemini 設計を採用）。
4. **議論を打ち切って投票へ** ボタンを常設。

### 5.6 パターンB（対面マルチ・A案）でのAI介入

- **AIの正本出力は全員のスマホに出るテキスト**（グループチャットのオーバーレイ）。スピーカーが1台も無くても成立。
- **音声は"雰囲気モード"**：卓中央の1台（記録者の座＝任意でBluetoothスピーカー）がTTSで読み上げる加点要素。無くてもテキストで読めるため破綻しない。「音声は演出、テキストが本体」。
- **AI発言は構造的な節目に限定**：CO直後・投票結果開示直後・定型質問への返答時。その瞬間に反応すれば会話に噛み合う（例「儂に2票も入ったか…誰じゃ」）。`aggression` 高キャラは節目で激しく噛みつけるので「寡黙なキャラ限定」ではない。唯一弱まるのは「生の口論に割り込む反射型」アーキタイプのみ。
- **メタ対策**：AIが常に静かだと「静か＝AI」と読まれるため、節目でしっかりバースト発言させ、AI比率を人間より控えめに保つ。

## 6. 初心者導線（人狼が初めての人）

3層で対応：

1. **開始前の30秒プライマー**：絵つき数枚で「村人 vs 隠れた人狼。昼＝話して1人追放、夜＝人狼が1人襲撃。人狼を全員見つければ村の勝ち」。スキップ可。
2. **その場ヒント（just-in-time）**：各画面に「今あなたが何をすべきか」を常時1行表示（既存 `screen-sub` を全画面で強化）。
3. **ソロAIモード＝練習台**：「ひとりで遊ぶ（AI対戦）」がプレッシャーなくルールを覚えるチュートリアルを兼ねる。MVP1 がそのまま入門体験になる。

## 7. アクセシビリティ（WCAG 完全準拠・ハード要件）

「完全にクリア」を **WCAG 2.2 AA を全箇所の必須基準、本文テキストは AAA（7:1）を目標** と定義する。

### 7.1 現状の問題（実測）

`design-system.css` / `mobile_app.html` は生成りテキストを低不透明度で多用：`rgba(237,233,220,0.55)` `0.58` `0.66`、トラック `0.1`。ダーク背景に対し、補助テキスト・注記・タブ非選択状態などで **AA（本文4.5:1／大字・UI 3:1）を下回る箇所が存在する**。

### 7.2 是正内容

- 全テキスト／アイコン／境界の色を監査し、**本文4.5:1以上（目標7:1）、大字・UIコンポーネント・フォーカスリング3:1以上**を満たすまで不透明度・色を引き上げる。「雰囲気のための薄さ」は可読性の一線を割らない範囲でのみ許容。
- **ルール等のタブ**：選択/非選択のコントラストを是正。
- **タップ領域 最低44×44px**、フォーカス可視、`prefers-reduced-motion` 対応、動的テキスト拡大への追従。
- スクリーンリーダー：役職確認・投票などの重要操作に適切なラベル／ロールを付与。役職秘匿を壊さない範囲で。

### 7.3 回帰防止

`tests/design_system_test.sh` に **コントラスト比の自動チェック**を追加し、基準未満の色定義をCIで失敗させる。実装時は `audit` / `accessibility` スキルを用いて体系的に実施する。

## 8. 亡霊（ghost_wolf）オプトイン＋説明

### 8.1 現状

「狼の亡霊（`ghost_wolf`）」は **カード（`mobile_app.html` のギャラリー）にのみ存在し、エンジン `roles.mjs` の26役職には未登録**＝現状は誰も亡霊で遊べない。要件は「将来遊べるようにする際、個別ON/OFFでき、説明を伴う」こと。

### 8.2 設計

- s07 役職構成に「特殊役職」欄を設け、亡霊を **デフォルトOFF・個別オプトイン**。
- トグル隣に必ず説明（初見者向け）：「人狼陣営の特殊役職。死んでも脱落せず、幽霊として議論・投票・襲撃相談に参加し続ける。人数カウントに含まれない。上級者向け。苦手ならOFFのままで。」
- デフォルトOFFの理由：知らないうちに入って混乱する事故をゼロにする。入れたい人だけが説明を読んで意図的にONにする。
- 実装時、エンジンに `ghost_wolf` を正式追加し、死亡後も行動可能な例外処理を通す（MVP2）。A案なのでAIに配られても破綻しない。

## 9. MVP ロードマップ

UIは最初からフル構造（席モデル・3モード・亡霊枠・アクセシビリティ）で作るが、中身は段階実装：

| フェーズ | 内容 | 主要な新規実装 |
|---|---|---|
| **MVP1** | パターンA「ひとりで遊ぶ（AI対戦）」。人間1＋AI（村人/人狼/占い師のみ）。人格2軸（logic/aggression） | ① AIオーケストレータ（Functions内で既存 `dispatchWerewolfCommand` をAIの `actorId` で叩く）② チャットUI 1画面 ③ 発言生成プロンプト＋検証パス ④ JSON Schema対象強制 ⑤ 卓設定画面（ソロ経路）⑥ アクセシビリティ是正の第一弾 |
| **MVP2** | 人格6軸フル＋主張台帳＋人狼の二重マトリクス＋カバーストーリー事前確定＋役職拡張＋亡霊トグル＋初心者プライマー | Step1完全版・Step2完全版・`ghost_wolf` エンジン追加 |
| **MVP3** | パターンB（対面・A案）＝みんなで＋AI補充・構造化アクションUI・議題フェーズ・TTS雰囲気モード・AI引き継ぎ | 疑い表明/議題UI・卓設定のマルチ経路・席引き継ぎ処理 |

**MVP1を最初にする理由：** このゲームの唯一の未検証仮説は「AIと議論して楽しいか」。エンジンも同期もアクセシビリティ基盤も検証済み資産の上に乗るので、その1点だけを最速で確かめる。

## 10. 破綻ポイントと回避策

| 罠 | 原因 | 回避策 |
|---|---|---|
| LLMに意思決定させる | 発言と投票の食い違いでゲーム崩壊 | 決定はコード、LLMは言語化のみ（本設計の根幹） |
| 生ログ全投入で嘘を忘れる | 文脈長の限界 | 主張台帳＋カバーストーリー事前確定 |
| 人狼AIの自爆・秘匿漏洩 | プロンプトに役職を書く以上必ず起きる | 「公開上の立場」と「真の知識」の欄分離＋出力検証＋秘匿漏洩の自動回帰テスト |
| ハルシネーション（死者告発・偽占い） | 対象の自由生成 | 選択可能リスト限定＋JSON Schema で対象ID強制 |
| コスト・レイテンシ | 全AI同時に大型モデル呼び出し | 小型高速モデル（Claude Haiku 級）＋ラウンド制発言権＋先読み生成＋反応AIを1体に絞る。重要ロジックはローカル数値計算（Step1） |
| AIが強すぎ／弱すぎ | logic高で毎回正解 | ノイズ項＋logic上限キャップ。人格パラメータ＝難易度スライダー |
| 音声認識に着手 | 対面音声を解こうとする | 帳面ルール（構造化アクション）で原理的に不要化 |
| 途中人数変更で破綻 | 勝敗計算の前提崩壊 | 席数不変。離脱はAI引き継ぎ、構成変更は再戦時 |

## 11. 既存資産との対応

| 必要なこと | 既存で使えるもの | 新規に作るもの |
|---|---|---|
| 役職配布・勝敗判定 | `game-engine`（シード配布・26役職） | 変更ほぼ不要（`ghost_wolf` 追加は MVP2） |
| AIの行動をゲームに反映 | `dispatchWerewolfCommand`（`actorId` 指定） | AIオーケストレータ（Functions内）で AI の `actorId` として叩く |
| 状態同期・秘匿 | RTDB＋セキュリティルール＋privateView | AIの秘匿知識は privateView をそのまま消費 |
| UI | `mobile_app.html`＋`design-system.css`（20画面） | 卓設定画面・チャットUI・構造化アクションUI・アクセシビリティ是正 |
| AI思考 | （なし） | `ai-brain.mjs`（Step1）＋プロンプト＋検証パス（Step2） |

## 13. 非目標（YAGNI）

- 対面フル音声のリアルタイム話者分離・認識。
- ゲーム途中の席数増減。
- B案リッチ（自由文ディクテーションをAIに読ませる）。
- AIキャラクターの詳細な手動人格エディタ（MVPではロスターから自動割当）。
