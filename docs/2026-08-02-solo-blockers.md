## 1. ② の設計判断 — 「延長」でも「復帰キー別発行」でもなく、役割を分けた

前回の宿題は「延長するのか、復帰キーを別に持つのか」だった。
コードを読んで、**どちらか一方では直らない**ことが分かったので二択を捨てた。

### なぜ延長だけでは直らないか

`game-client/firebase-game-client.mjs` は `roomId` を**メモリにしか持っていなかった**。
ブラウザを再読み込みすると `currentRoomId` が消え、戻る方法が一つも無い。
入口は `joinRoom({code})` だけで、しかもその合言葉は — TTL をどれだけ延ばしても —
`joinSnapRoom` が満室・配役の都合で**始まった卓には使えない**。

> つまり TTL は「途中復帰できない」の原因ではなく、**症状の一つ**でしかなかった。
> 5分を1日に延ばしても、リロード1回で同じ場所に戻れなくなる。

### なぜ復帰キー別発行も採らないか

新しい鍵を作れば、**その鍵を保存し・見せ・入力させる**画面が要る。
だが復帰に必要な識別子は既に存在している — **匿名認証の uid** だ。
Firebase Auth がブラウザに保存しているので、リロードしても同じ人のままである。
そして `roomMembers/{roomId}/{uid}` が既にサーバーにある。
**足りなかったのは鍵ではなく、それを使う関数だった。**

### 採った設計 — 合言葉と復帰を別の道にする

| | 合言葉（`joinSnapRoom`） | 復帰（`resumeRoom`・新設） |
|---|---|---|
| 何のため | **まだ入っていない人**を入れる | **既に席がある人**を戻す |
| 識別子 | 6文字のコード | `auth.uid` |
| 寿命 | 12時間（5分から） | **無し** |
| 締切 | 時計ではなく**卓の状態**（`waiting` の間だけ） | 無し。`playing` でも `finished` でも戻れる |
| 画面 | 合言葉を入力 | 「前の卓に戻る」（部屋選びに出る） |

決め手は3つ。

1. **時計で締め切るのをやめた。** 新規参加を止めたい本当の理由は「始まった卓に
   人を入れると配役が壊れるから」であって、5分経ったからではない。
   だから判定を `meta.status !== 'waiting'` に移した。TTL の12時間は
   「6文字の合言葉空間を無期限に占有させない」ためだけに残した上限で、
   **遊んでいる人が踏むことはもう無い**。
2. **既に一員なら、寿命も卓の状態も問わず合言葉を通す。** 保険。
   復帰導線を知らない人が古い合言葉を打っても、その人が元メンバーなら入れる。
3. **復帰の控えは合言葉ではなく `roomId` を保存する。** 合言葉には寿命があるが、
   席には無い。`localStorage` に12時間分だけ持ち、古い控えは**最初から出さない**
   （押して失敗するより、出ない方がよい）。

### 残した穴（意図的）

- リロード直後に着地するのは**タイトル画面**で、自動復帰はしない。
  「前の卓に戻る」は部屋選び（s02）に出る。**タップが1回増える**。
  自動で戻すと「新しく遊びたいのに前の卓へ引き戻される」方が事故として重いと判断した。
- プライベート閲覧では `localStorage` が使えず、復帰の控えが残らない。
  遊ぶことはできる。復帰だけができない。

## 2. ① AIが喋らない — 「鍵が無い」を失敗ではなく状態として扱う

### 何が起きていたか

鍵が無いと `generateSpeech` が全AI分だけ例外を投げ、`errors++` されて
**1件も chat に入らないまま昼が終わる**。夜行動と投票はローカルの `ai-brain` で
動いているので、**行動はするのに一言も喋らないAI**になる。
画面には何も出ないので、原因が鍵だとは誰にも分からない。

### 直し方

**鍵の有無で分岐を変えた。** `functions/index.js` は鍵が空なら `deps.generate` を
`null` で渡す。orchestrator はそれを見て、最初からローカル発話に落とす。

ローカル発話（`functions/ai/fallback.mjs`）は LLM に課しているのと同じ制約を守る:

- **`decideVote` の結論とずれない**（投票予定の相手を必ず名指しする）
- 名簿（生存者）にない人物に言及しない
- 100文字以内・`validateUtterance` の禁止語を含まない
- 人格（logic / aggression）で口調が3系統に分かれる
- **決定論**。同じ卓・同じラウンドなら毎回同じ文になる（`Math.random` 不使用）

```
虎鉄:紗奈について確認したい。言っていることが噛み合わないのはなぜ。
紗奈:虎鉄、さっきから話がずれてる。言っていることが噛み合わないだと思う。
凛:私は虎鉄を疑っている。根拠は言っていることが噛み合わない。
ゴン:オレは虎鉄を推す。言っていることが噛み合わない。ここで決めないと押し切られる。
```
（鍵無しで実際に生成されたもの）

### これは「症状を隠す fallback」ではない

`/superforge-debug` が禁じている dummy fallback と紛らわしいので、境界を引いておく。

- ローカル発話は chat に **`source:"local"`** が付く。あとから全部判別できる
- `advanceAiTurn` は **`speechMode`（`llm` / `degraded` / `local`）** を返す
- 画面は簡易モードのとき**トーストで一度だけ知らせる**
- 生成の失敗は**引き続き `errors` に数え、`console.error` に出す**。
  埋め合わせても、失敗した事実は消さない

つまり「動いているように見せる」のではなく、**動かない理由を表示したまま遊べる**
状態にした。

### 鍵の確認はユーザーの端末でしかできない — なので手順を用意した

このエージェント環境に鍵は無い（`functions/.secret.local` はダミー）。
デプロイもできない。そこで**デプロイせずに鍵だけ試せる**スクリプトを置いた。

```bash
ANTHROPIC_API_KEY='sk-ant-...' node functions/scripts/check-anthropic-key.mjs
```

401 / 429 / 残高 / 未設定 を出し分けて、次にやることを1行で出す。
手順表は `docs/deploy.md` §2。

> なお `api.anthropic.com` へはこの環境からも到達できる（偽の鍵で 401 が返ることを
> 実際に確認した）。到達性は問題ではなく、**鍵の有無だけ**が問題である。

## 3. ③ 会話が成立していなかった — 発言ログと、返しの波

### 渡していなかったもの

`orchestrator.mjs` には `recentUtterances: []` が**ハードコード**されていた。
`structuredLog` も生存者一覧だけで、**昨夜誰が死んだのかすら入っていなかった**。
これでは人間が何を書いても、AIには見えていない。

`deriveChatDigest` / `deriveTableLog`（`context.mjs`・純関数）を足して渡した。

- 直近6件の発言を `名前: 本文` で渡す
- **死亡者の発言は落とす**。名前を出すと「名簿にない人物への言及」を誘発して
  `validateUtterance` に落ちる発話が増えるため
- 帳面に「昨夜の犠牲」「前回の処刑」「同数で処刑なし」を入れた

### それでもまだ会話にならなかった — 発話が昼の頭で終わっていた

AIの発話は昼の**開始と同時に1回**流れて終わりだった。人間が読んで返事を書く頃には
もう誰も喋らない。ログを渡しても、**AIが人間より先に喋り終えている**ので反応しようがない。

**発話を「波」に分けた。**

| 波 | いつ | 誰が |
|---|---|---|
| 1波目 | 昼の開始 | 生存AI全員（第一声） |
| 2〜3波目 | **人間が発言してから約1.4秒後** | 最大2体。**名指しされたAIを優先** |

- 上限は3波（`MAX_DAY_WAVES`）。サーバー側で強制するので、連投しても増えない
- 人間の発言が無い波は**空振りせず何もしない**（LLM を焼かない）
- 1波目の claim キーは従来のまま（`{round}_{phase}`）。進行中の卓を壊さない
- クライアント側は1.4秒のデバウンス。連投しても波は1つ

これで「言う → 返ってくる → 言い返す」が2往復できる。
