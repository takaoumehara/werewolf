## 2. C（発表可能にする7項目）

### ① QRを読んだ所からの遊び方説明 — 完了
4枚の説明オーバーレイ（`#howtoOverlay`）を追加した。
- `?room=CODE` で開いた人には、**合言葉を入れる前に一度だけ自動で開く**（`localStorage` で2回目以降は出ない）
- タイトル画面・合言葉画面・ルールドロワーからいつでも開き直せる
- 内容: ①どんな遊びか ②役職は自分だけが見る（長押し）③夜→朝→議論→投票 ④勝利条件

**なぜここか**: QRから来る人はアプリの存在も人狼のルールも知らない。
最初の接点は合言葉画面なので、そこに置いた。

### ② この卓の役職構成を全員に見せる — 完了
エンジンの公開ビューに **`roleComposition`** を追加した（`game-engine/src/engine.mjs`）。
物理の人狼で「使う札を見せてから配る」のと同じ情報で、**誰が何を持つかは含まない**。
- 並びは `roleId` の昇順に固定（席順から配役を逆算できないように）
- テスト2件で、IDが漏れないことと席順に依存しないことを保証

画面側はルールドロワーに **「この卓」タブ**を新設し、構成・生死・出来事の記録をまとめた。

### ③ 結果画面の自動送り停止 — 完了
夜の訪れ / 朝の記録 / 同票 / 評決 の4画面は **1.6〜2.4秒で勝手に流れていた**。
読み終わる前に消えるので「誰が死んだのか分からないまま議論が始まる」状態だった。

- 自動送りのタイマーを**全廃**（`scheduleInterstitial` は待つだけになった）
- 「読んだ ／ 次へ」を主ボタンにして、押すまで待つ
- 卓は先へ進み続けるので、**待っている間に卓が動いたらその場で知らせる**
  （`.catchup-hint` 「卓はもう先へ進んでいます。押すと追いつきます。」）
- **「戻れる」の実装**: 一度きりの表示に戻るのではなく、
  「この卓」タブの**出来事の記録**にラウンドごとの死亡が全部残る。いつでも読み返せる。

### ④ 生死の常時表示 + 終局カードの拡大 — 完了
- **生存者ストリップ**（`#aliveStrip`）を卓の進行中ずっと出す。
  `生存 5/8` と全員の名前。死亡者は取り消し線＋破線枠。押すと「この卓」が開く
- 終局の札に **「死亡」バッジ**を足し、グレースケールを 0.65→0.95 まで強めた
  （従来は「少し暗い」だけで、生死が読み取れなかった）
- 終局の札は元々タップで全画面になっていたが、**「この卓」の構成一覧からも札を開ける**ようにした

### ⑤ 役職構成画面の余白を詰めて札を大きく — 完了
- 見出しと合計を1行に統合、説明とプリセットを圧縮（縦を約90px 回収）
- **狭い端末で 3列 → 2列**。1枚あたり 113px → **176px（約1.5倍）**
- ± ボタンの幅も 38px → 52px 以上になり、押し間違いが減る
- **44pt のタップ下限は守った**（一度 40pt に下げて `viewport_fit_test` に落とされ、戻した）

### ⑥ 図鑑の入れ子と札の頭切れ — 完了
- **入れ子スクロール**: ドロワー自身とタブ面が両方 `overflow-y:auto` で二重になっていた。
  スクロールするのはタブ面だけにし、`min-height:0` を足して実際に効くようにした
- **頭切れ**: サムネの画像が `height:128%` を下端に揃えていたため、
  はみ出した 28% が上から切り落とされ、**ほぼ全役職で顔が写っていなかった**。
  枠内に収める指定に変え、枠も 72×84 → 76×100 に広げた
- フィルタのチップ（4個）が 393pt で1行に入らず「第三陣営」が切れていた → 折り返す

### ⑦ トップバー整理と音が鳴らない — 完了

**トップバー**: 5ボタン（映像・制作・♪・進める・ルール）が 393pt で潰れていた。
- **映像／制作はタイトルと部屋選びでだけ出す**（卓の最中は意味を持たない）
- 音トグルは `♪` だけの 0.55 不透明度で、オンかオフか、そもそも何のボタンかも読めなかった
  → **`♪ オン` / `♪̸ オフ` と文字で状態を出す**
- 380pt 未満ではさらに詰める

**音が鳴らない — 原因は「壊れている」ではなく「小さすぎる」だった。**
`OfflineAudioContext` で実際の信号経路（発振器 → ローパス → ambient → コンプレッサ → master）
をレンダリングして測った:

| | ピーク | RMS |
|---|---|---|
| 修正前 | **−36.5 dBFS** | −44.5 dBFS |
| 修正後 | **−19.4 dBFS** | −27.4 dBFS |
| 差 | **+17.1 dB** | |

−36.5 dBFS はスマートフォンのスピーカーでは無音と区別がつかない。
`MASTER_LEVEL` 0.62→0.85 / `AMBIENT_BASE` 0.26→0.55 / ドローン3層の gain を約2.4倍にした。

あわせて3つ直した:
1. **立ち上がりが 2.8〜3秒**あり、押しても変化が分からず「効かないボタン」に見えた → 0.9〜1.4秒
2. **解除した瞬間に必ず一音鳴らす**（押した手応えが無かった）
3. **終局後にミュート解除すると無音のままだった** — `finished` を再送すると
   `stopDrone` するだけだったため。`calm_resume` を足して落ち着いた空気で鳴らし直す

## 4. B — アプリ内の「ゆらゆら」（容量ゼロ）

AI動画を使わず CSS だけで作った。**配信物は1バイトも増えていない**。
動かすのは `transform` と `opacity` だけ（合成のみで再描画が起きない）。

- **霧**: 大きな放射グラデーション2枚が、41秒と67秒の別々の周期で流れる
- **灯り**: 13秒周期の不等間隔で息をする（等間隔だと点滅に見える）
- **フェーズごとの性格**: 夜は青く遅く（19秒）、昼は静か、投票は速く落ち着かない（7秒）、終局は24秒
- **札のゆらぎ**: 役職確認とカード全画面で札そのものが呼吸する
- `prefers-reduced-motion` では全部止めて静かな1枚絵になる

**踏んだ罠**: 最初 `.card-wrapper` に当てたが、そこは `fitCardToSlot` が拡大率を書き込む場所で、
アニメーションが勝って札の大きさが壊れる。枠（`#roleCardSlot` / `#cardFullscreenSlot`）に移した。
